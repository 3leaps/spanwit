# spanwit v0.3.0

## Overview

A coordination release. An experimental daemon observes disk capacity and,
with an active profile, proposes reclaim without executing it. Every
`prune --execute` on macOS and Linux is recorded in a local journal, and an
exact plan can be approved once, with a hardware security key, for someone
else to run. Deletion remains dry-run by default.

## Highlights

- **One-shot approvals** (macOS and Linux): `spanwit approval` lets a maintainer approve one exact prune plan, once, within at most 24 hours, with a touch on an OpenSSH security key listed in a file the executing user cannot write. Execution re-checks the plan, signature catalog, `--min-age` and optional profile activation, and refuses on any difference. See the [one-shot approval guide](../guides/one-shot-approval.md).
- **Journaled execution**: each `prune --execute` records the candidates it will attempt before the first deletion and each candidate's outcome. `spanwit approval operation <id>` reports them after an interruption, with `unknown` where no outcome was recorded.
- **Observation daemon (experimental, macOS and Linux)**: `spanwit daemon run` samples capacity into a private journal and serves read-only status to the same user. Optional roots add bounded allocation observations. `spanwit daemon service` installs a launchd or systemd user service that starts only when asked. See [the daemon guide](../observe-daemon.md).
- **Profile packs (experimental)**: personas group cleanup recipes with optional cache budgets and free-space objectives. `profile preview` uses the existing planner; an activated profile drives daemon proposals, which never authorize execution. See [profile packs](../profile-packs.md).
- **Relocated build caches**: a `CARGO_TARGET_DIR` or Go build cache moved elsewhere is recognized by its own markers.
- **Allocated sizes and replay freshness**: sizes are bytes allocated on disk, and exact-plan replay withholds candidates that changed or saw activity since the plan.

## Behavior changes

- `prune --execute` refuses while the daemon is running. Stop it (Ctrl-C in the foreground, or `spanwit daemon service stop`), prune, then start it again.
- On macOS and Linux the state directory (`~/.local/state/spanwit/daemon`, or `--state-dir`) must be on a local APFS or HFS+ (macOS) or ext4, XFS or Btrfs (Linux) filesystem. Otherwise `prune --execute` refuses before planning and deletes nothing.
- On Windows `prune --execute` keeps the earlier unjournaled behavior and reports `journal: unavailable_on_platform`; `--approval` is refused.
- Replay applies a 1h minimum idle age to every candidate; `--config` is refused in replay modes.
- Sizes are allocated bytes, so small trees read larger and a low `min_size` may admit rows it previously withheld.

## Release provenance

- Release tags are GPG-signed and verify against [`docs/security/release-signing-keys.asc`](../security/release-signing-keys.asc) (fingerprints in [`keys/expected-fingerprints.txt`](../../keys/expected-fingerprints.txt)). Verify with `git tag -v v0.3.0` after importing that key.
- Checksum manifests are signed with minisign and PGP; the published assets are byte-identical to the signed set.

## Install

```bash
brew install 3leaps/tap/spanwit                      # macOS Apple Silicon, Linux
go install github.com/3leaps/spanwit/cmd/spanwit@v0.3.0
```

```powershell
scoop bucket add 3leaps https://github.com/3leaps/scoop-bucket
scoop install spanwit
```
