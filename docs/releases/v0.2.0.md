# spanwit v0.2.0

**Diagnostic and evidence release.** Spanwit now explains where disk space went
before it suggests reclaiming any of it. The new diagnostic surfaces report what
they observed, what they could not observe, and how much the numbers can be
trusted. Deletion remains dry-run by default.

## Highlights

- **`space`**: read-only disk diagnostic. It reports pressure, verified
  reclaimable space, diagnostic-only cache and toolchain hotspots, and guided
  recipes, and hands off exactly to `prune`. Capacity accounting
  (`--capacity-only`), held-open capture and `--compare` are included.
- **`inventory`**: bounded, read-only filesystem inventory with a typed JSONL
  profile, explicit coverage gaps, exclusions, `--summary-only`, directory
  summaries and typed directory accounting.
- **Readable folder audit**: `inventory --directories --directory-min-size 5GiB`
  lists the largest folders by allocated size. Lower bounds and unavailable
  sizes are shown honestly, never as zero. `--format jsonl` emits the
  `spanwit.filesystem-inventory-aggregation/v2` profile with a
  [published schema](../../config/schema/spanwit-filesystem-inventory-aggregation.v2.schema.json).
- **Coverage attestation**: `--coverage-attest PATH` writes a separate, validated
  `coverage-attestation/v0` document, for file inventories and for the folder
  audit. Writing it is a mutation, so `--read-only` rejects the flag. Path
  scopes are opaque. Failed or canceled audits withhold it.
- **`diagnose`**: file-level diagnostics.
- **`observe`**: samples registered volumes and emits dry-run-safe proposals.
  It keeps local state under `--state-dir`, so it is not read-only and
  `--read-only` rejects it.
- **`--read-only`** (or `SPANWIT_READ_ONLY`): fail-closed assertion that the
  invocation performs no mutation, checked before any discovery.
- **Structural recipes**: guided multi-step journeys, starting with Cargo
  `target/` relocation.
- **Safety**: a shared destructive-path guard, `safe_to_prune` enforcement with
  withheld candidates, and terminal-safe rendering of hostile path names.

## Breaking changes (alpha)

- Config age fields are renamed and flipped: `min_age` is the older-than floor
  and `max_age` is a younger-than ceiling. Update hand-written configs that used
  the old `max_age` floor.
- `spanwit-prune-plan/v1` gained required fields in place. Validate against the
  schema shipped with the matching spanwit version.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list.

## Release provenance

- Release tags are GPG-signed and verify against the public key committed in
  [`docs/security/release-signing-keys.asc`](../security/release-signing-keys.asc)
  (fingerprints in [`keys/expected-fingerprints.txt`](../../keys/expected-fingerprints.txt)).
  Verify locally with `git tag -v v0.2.0` after importing that key.
- Release builds run in a read-only workflow; the maintainer creates and
  publishes the release after re-verifying the tag. See
  [ADR-0005](../decisions/ADR-0005-release-publication-gate.md).

## Toolchain & quality

- Go 1.26.x (patched toolchain enforced); gofulmen v0.3.6.
- Release artifacts: binaries for linux (amd64, arm64), windows (amd64, arm64)
  and darwin (arm64), with SHA256/SHA512 manifests signed in the manual signing
  ceremony before the draft release is published.
