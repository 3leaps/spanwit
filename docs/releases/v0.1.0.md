# spanwit v0.1.0

**Initial release** — context-aware, signature-driven disk-reclamation CLI.

Spanwit recognizes regenerable build output by context (a `target/` next to a
`Cargo.toml` is fair game; an identically named directory elsewhere may not be)
and reclaims it safely. Dry-run by default, pipeline-friendly, built on the
Fulmen microtool chassis (gofulmen + Crucible standards).

## Highlights

- **`scan`** — read-only analysis; reports reclaimable directories above a size threshold.
- **`prune`** — plan and (with explicit `--execute`) delete reclaimable directories. Dry-run is the default; `--format json` emits a schema-validated prune plan for pipelines.
- **Signature-aware config** — a directory is reclaimable only when its context matches, not by name alone. Driven by a YAML config validated against a JSON Schema.
- **Standard microtool surface** — `version`, `envinfo`, `doctor`, plus `validate` (schema/data validation).
- **Strict stdout purity** — results on stdout, all logs/diagnostics on stderr ([ADR-0001](../decisions/ADR-0001-stdout-purity.md)).
- **Dry-run by default** as a product-wide invariant scaling to the future daemon/control-plane ([ADR-0002](../decisions/ADR-0002-dry-run-default.md)).

## Identity & configuration

- Binary `spanwit`; env prefix `SPANWIT_`.
- Config resolution: `--config` flag → `SPANWIT_CONFIG_PATH` → `~/.config/spanwit/config.yaml`.

## Toolchain & quality

- Go 1.26.x; built and tested on the `goneat-tools-runner-glibc` CI image.
- Quality gates: `make pr-final` (PR gate), `make prepush` (tag/pushtag gate).
- Release artifacts: binaries for linux (amd64, arm64), windows (amd64, arm64), and darwin (arm64), with SHA256/SHA512 manifests; manifests signed via the manual signing ceremony (minisign primary, PGP optional) before the draft release is promoted to public.
